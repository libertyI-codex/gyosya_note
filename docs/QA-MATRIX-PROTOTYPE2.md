# 買取業者ノート Prototype2 QAマトリクス

対象：Kaitori Company Note — Ver.1.0 試作2  
目的：Prototype1の業者ノート機能を維持しながら、案件・業者回答・業者履歴・類似案件を追加するDB version 2の品質を確認する。

## 1. QA方針

- 必須62項目は、番号を変えずに本書で追跡する。
- IndexedDB移行・原子性・参照整合性は、画面表示だけでなく保存データを直接確認する。
- 正規化・検索・類似判定・履歴集計・CSV生成は、可能な限り純粋関数の単体検査にする。
- 登録・編集・複製・削除・ダイアログ・レスポンシブは実ブラウザで確認する。
- Prototype1の既存49項目は削除せず、回帰スイートとして継続実行する。
- テストデータは実在しない名称、固定ID、固定ISO日時を使い、順序検査を再現可能にする。

## 3. 性能・容量QA（必須62項目への追加）

性能テストは端末差を考慮し、厳しいベンチマークではなく明確な退行検出を目的とする。`tests/qa-case-performance.cjs`は結果と経過時間を標準出力へ記録する。

| データ規模 | fixture | 検査 | 初期ガードレール |
|---:|---|---|---:|
| 1,000 | cases | 正規化、案件検索 | 各バッチ 3,500ms未満 |
| 1,000 | cases | 類似候補を代表25案件について連続算出 | 7,000ms未満 |
| 500 | companies | 正規化・一覧sort | 各バッチ 2,000ms未満 |
| 500＋10,000 | companies＋caseResponses | 代表250業者の履歴を連続集計し全件数と照合 | 5,000ms未満 |
| 1,000＋10,000 | cases＋caseResponses | 正規化、案件回答CSV | 各バッチ 5,000ms未満 |

ガードレールはMicrosoft Edge／同梱Node実行環境のCI退行検出値であり、iPhone実機の応答時間保証ではない。各計測前にfixture生成時間を分離し、最低1回のwarm-up後に測る。

## 4. Prototype1 QAを維持する差分

### そのまま維持する契約

- 業者登録・編集・複製・削除・検索・お気に入り・温度感・連絡リンク。
- Prototype1の業者CSV 11列、UTF-8 BOM、CRLF、CSV injection対策。
- v1 JSONの検証と復元互換性。
- 390px／390×500／1440px、file／HTTP／PWA／offline、アイコン、外部依存なし。
- 初期サンプル3社の識別と、`sampleInitialized`による再追加防止。

### 既存QAで更新が必要な固定値

| 既存箇所 | Prototype1期待 | Prototype2期待／対応 |
|---|---|---|
| `tests/qa-static.cjs` DB version | `1` | `2`。v2専用契約は`S2`へ分離し、旧テストの固定値を更新する |
| `tests/qa-static.cjs` stores | companies/settings | cases/caseResponsesを追加確認 |
| `tests/qa-static.cjs` cache | `kaitori-company-note-v1-prototype1` | Prototype2 cache名へ更新 |
| `tests/qa-browser.cjs` cache検査 | prototype1 cacheが現行 | prototype1を旧cacheとして削除し、prototype2を保持 |
| `tests/qa-browser.cjs` 下部ナビ | 3画面前提 | 既存3画面の動作を保ち、案件を加えた4画面を確認 |
| `tests/qa-unit.cjs` backup | schemaVersion 1のみ | v1互換を残し、v2完全backupを追加 |
| `clearAllData`利用箇所 | 2 store初期化 | cases/caseResponsesも消去し、テスト間を隔離 |

既存テスト名やPrototype1証跡は削除せず、更新前の結果とPrototype2の結果を区別して保存する。

## 5. 未自動化・環境依存項目

次は自動QAの結果を過大に表現しない。

- iPhone実機Safariでのホーム画面追加、safe area、ソフトウェアキーボード表示中の操作。
- OSの電話・メールアプリの実起動。自動QAは`tel:`／`mailto:` URIまで。
- Microsoft Excel実アプリでの目視。自動QAはBOM、CRLF、列、escapeまで。
- Safariのストレージ削除・容量圧迫・OSによるサイトデータ退避後の永続性。
- GitHub Pagesの実公開URL。自動QAは同等のHTTPサブパスと相対URLまで。
- 500／1,000／10,000件のNode計測値は実機iPhoneの性能保証ではない。
- IndexedDBのtransaction失敗注入は、実装に安全なテストフックがない場合、B2で一時的な制約違反を発生させる方法を採用する。安全に注入できない場合だけNo.47を手動検査として明示する。

# 買取業者ノート

**Kaitori Company Note — Ver.1.0 試作3**

不動産の買取案件が発生したときに、相談先の検索、案件概要、各社の回答金額・条件・見送り理由を少ない入力で端末内へ記録するローカルWebアプリです。本格的なCRMではなく、「どの業者へ相談するか」「似た案件で誰がどう回答したか」を短時間で確認する用途に限定しています。

ログイン、外部サーバー、外部API、CDN、クラウド同期は使用しません。データはブラウザのIndexedDBへ保存します。

## Ver.1.0 試作3の変更点

- 下部ナビを「探す／案件／業者／その他」の横1段4列へ固定しました。
- 案件画面への遷移を単一ルーターへ集約し、アイコン・文字・余白のどこからでも1回のタップで開けるようにしました。
- 業者登録などのダイアログを、固定ヘッダー、本文だけのスクロール、固定フッターの3領域へ統一しました。
- 業者名よみがな、IME入力中の読み候補、カタカナからひらがなへの候補変換を追加しました。
- 買取エリアへ千葉を追加し、神奈川県全域・関東・全国の一括選択と包含検索に対応しました。
- 業者の買取対象を、案件種別10項目と個別要因17項目の共通カタログへ統一しました。
- 買取対象へ「全て」「すべて解除」「その他補足」を追加しました。
- 選択チップは選択前後で文字サイズ、余白、境界線幅、高さが変わらない設計にしました。
- 試作3では温度感を登録・表示・検索・並び替え・統計・おすすめ判定・新規CSV・新規JSONから削除しました。
- JSONを `schemaVersion: 3` へ更新し、試作1・試作2のバックアップを引き続き復元できます。
- IndexedDBはversion 2のまま維持し、業者、案件、回答、設定を失わずデータモデルだけを冪等に補完します。

## 起動方法

### `file://` で直接起動

`index.html` をダブルクリックします。業者・案件・回答の登録、検索、編集、JSON、CSVは利用できます。ブラウザの制約によりService Worker、PWAインストール、オフラインキャッシュは利用できません。

### ローカルHTTPサーバー

このフォルダで次を実行し、`http://127.0.0.1:8765/` を開きます。

```powershell
python -m http.server 8765
```

HTTP起動ではService Workerとオフラインキャッシュを利用できます。

### GitHub Pages

フォルダ一式をGitHub Pagesへ配置できます。アセットは相対パスで参照しています。PWAとして使う場合はHTTPS配信が必要です。

## 画面構成

下部ナビは390px幅でも常に横1段です。

1. **探す** — エリア、買取対象、お気に入り、フリーワードで業者を検索
2. **案件** — 案件一覧、各社回答、類似案件を確認
3. **業者** — 業者一覧、絞り込み、回答履歴を確認
4. **その他** — 件数、次回確認、バックアップ、CSV、詳細設定

右下の「＋」は、探す・業者では新規業者、案件では新規案件を開きます。案件の画面遷移、見出し、選択状態、`aria-current`、一覧再描画、＋ボタンの用途は同じルーターで同期します。

## 業者登録

「探す」または「業者」で右下の「＋」を押します。必須項目は**業者名だけ**です。

- 業者名
- 業者名よみがな
- 担当者名
- 電話番号
- メールアドレス
- 買取エリア
- 買取対象
- その他補足
- お気に入り
- 一言メモ

会社名は前後空白と連続空白を整理し、電話は数字・ハイフン・括弧を許容します。メールは前後空白を除去します。同名、正規化した同名、電話、メールが一致すると重複候補を表示しますが、同名別会社として続行できます。

登録ダイアログは固定ヘッダー、スクロールする本文、固定フッターで構成します。`100dvh` を優先し、`100svh` と `100vh` をフォールバックに使用します。開いている間だけ背景を固定し、閉じるとスクロール位置を復元します。狭い画面やキーボード表示時にはVisualViewportの高さを反映します。

## 業者名よみがな

保存項目は `companyNameKana` で、任意入力です。検索と業者名順では、よみがながある業者は `companyNameKana`、ない業者は `companyName` を比較キーにします。検索時はNFKC、空白整理、英字の大小文字無視、カタカナからひらがなへの変換を行います。

業者名入力では `compositionstart`、`compositionupdate`、`compositionend`、`beforeinput`、`input` を監視します。IMEが漢字変換前の読みをブラウザへ渡した場合だけ、その読みを候補としてよみがな欄へ入れます。カタカナ部分はUnicodeの対応範囲でひらがなへ変換します。

ブラウザだけで確定済みの任意の漢字を正確に読めないため、漢字からの推測はしません。IMEの情報量はOS・ブラウザ・入力方式に依存します。既存値がある場合、または利用者がよみがなを一度手動編集した後は、自動候補で上書きしません。候補はいつでも修正できます。

## 買取エリア

共通の内部IDと表示ラベルを分離して管理します。

- 横浜、川崎、湘南、県央、横須賀・三浦、県西
- 神奈川県全域、東京都、千葉、関東、全国、その他

広域項目には次の一括選択があります。

- **神奈川県全域** — 自身と横浜、川崎、湘南、県央、横須賀・三浦、県西を選択
- **関東** — 全国とその他を除く全項目を選択
- **全国** — その他を除く全項目を選択

広域項目をOFFにしても展開済みの個別項目は残ります。「すべて解除」で明示的に消せます。手動で下位項目をそろえても広域項目を自動選択しません。

検索・おすすめ判定では保存方法にかかわらず包含関係を解釈します。神奈川県全域は横浜案件、関東は千葉案件、全国は通常エリアの案件へ一致します。その他は自動包含しません。

## 買取対象

案件と業者は同じ内部IDカタログを使用します。

### 案件種別（10項目）

- 戸建1宅地
- 戸建分譲
- 一棟収益
- 区分M（空室）
- 区分M（OC）
- 土地
- 事業用地
- 店舗・事務所
- ビル
- その他

### 個別要因（17項目）

- **建築・造成** — 旧耐震、造成、崖・擁壁、狭小地、旗竿地、不整形地、再建築不可
- **権利関係** — 借地、底地、立ち退き
- **法令・土地特性** — 調整区域、山林、農地、既存不適格、埋蔵文化財
- **売却事情・商品特性** — リースバック、事故・心理的瑕疵

業者登録の先頭にある「全て」は、案件種別のその他を除く9項目と個別要因17項目を一括選択します。その他は自動選択しません。「全て」をOFFにしても展開済みの各項目は残り、「すべて解除」で消せます。「全て」は操作用の仮想項目で、検索対象の実データにはしません。

案件種別の「その他」を選ぶと「その他補足」へホテル、工場、倉庫などを300文字まで保存できます。選択を一度外しても補足文字列は勝手に消さず、検索対象にも含めます。

業者カードは対象を先頭数件と「ほか○件」で要約し、詳細では全項目をカテゴリ別に表示します。

## 旧買取対象の移行

試作1・試作2の `propertyTypes` は削除せず、起動時に新しい `purchaseTargetIds` へ変換します。土地、一棟収益、店舗・事務所、ビル、借地、底地、再建築不可、調整区域、事故・心理的瑕疵など、一意に対応できる値だけを共通IDへ移します。一棟アパートと一棟マンションは一棟収益へまとめます。

「区分マンション」のように空室かOCかを一意に決められない値や、固定候補に対応しない旧値は `legacyPurchaseTargets` へ残します。`customPurchaseTarget` も保持します。移行済みフラグと重複除去により、再起動しても値は増えません。旧の元フィールドも互換保護のためIndexedDB上で強制削除しませんが、試作3の新規保存・表示・検索は新モデルを使用します。

## 買取業者の探し方

エリアと買取対象は複数選択でき、異なる分類はAND、同じ分類内はORです。お気に入りのみも指定できます。フリーワードは次を横断します。

- 業者名、業者名よみがな、担当者名
- 電話、メール
- 買取エリア
- 案件種別、個別要因、旧対象
- その他補足、一言メモ

探す画面はお気に入りを先にし、同順位ではよみがなまたは業者名順です。業者画面では業者名順、お気に入り順、更新が新しい順、登録が新しい順を選べます。

## お気に入り

業者カードと詳細画面の星でワンタップ切替できます。お気に入りは検索結果上位と、案件へ追加するおすすめ順位に反映します。

## 案件登録と各社回答

案件登録は案件名だけで保存できます。所在地、エリア、案件種別、案件状況を先に表示し、個別要因、売主希望額、土地・建物面積、案件メモは詳細内にまとめています。

案件状況は相談中、買取打診中、回答待ち、回答済み、成約、見送りです。各社回答は打診済み、回答待ち、金額回答、条件付き、見送り、成約です。同じ案件・業者は1回答に限定します。回答金額、回答日、回答理由、回答関連要因、次回確認日、回答メモは任意です。

回答理由は、金額が合わない、エリア外、物件種別対象外、個別要因が難しい、現在仕入れ休止、社内稟議否決、他案件を優先、条件付きなら検討可、その他です。回答関連要因は案件側の要因から選びます。案件から後で外れた要因も回答履歴から勝手に消しません。

## おすすめ業者と類似案件

案件へ業者を追加するときは、次をローカルで加点します。

- エリア一致
- 案件種別一致
- 個別要因の一致数
- お気に入り
- 同じ種別・要因を含む過去の類似案件回答
- 過去の成約履歴

候補カードでは案件種別一致と個別要因一致数を分けて表示します。アーカイブ済み、追加済みの業者は候補へ出しません。

類似案件は、案件種別一致、個別要因の一致数、エリア一致、更新日の新しさの順に単純スコアリングし、同じ案件自身を除外します。外部AIや外部APIは使いません。

## 業者回答履歴とアーカイブ

業者詳細には回答案件数、金額回答、見送り、成約、最近の回答、対応案件種別・個別要因を表示し、案件を開けます。回答履歴がある業者を通常削除すると完全削除せずアーカイブします。通常一覧と新規候補からは非表示になりますが、過去回答には業者名が残り、詳細設定から復元できます。

案件削除時は紐づく回答も同一トランザクションで削除します。確認文には回答件数を表示します。

## JSONバックアップと復元

「その他」から業者、案件、回答、設定を1ファイルへ保存します。

```json
{
  "format": "kaitori-company-note-backup",
  "appName": "買取業者ノート",
  "appVersion": "Ver.1.0 試作3",
  "schemaVersion": 3,
  "exportedAt": "ISO 8601日時",
  "companies": [],
  "cases": [],
  "caseResponses": [],
  "settings": {}
}
```

試作3の会社データには `companyNameKana`、`purchaseTargetIds`、`customPurchaseTarget`、`legacyPurchaseTargets` を含みます。復元は「現在のデータへ追加」と「現在のデータを置換」の2方式です。追加時はID衝突を新しいIDへ付け替え、回答参照も追従します。置換は全ストアを同一トランザクションで処理します。

`schemaVersion: 1` と `schemaVersion: 2` も復元できます。旧バックアップの業者名よみがなは空文字として扱い、旧対象を互換移行します。旧レコードに残る温度感フィールドは復元拒否の理由にせず、試作3の通常データには取り込みません。ID、参照先、同一案件・業者の重複、案件種別、要因、回答状況、金額、日付を保存前に検証し、失敗時は既存データを変更しません。

## CSV出力

- **業者一覧CSV** — 業者名、業者名よみがな、担当者名、電話番号、メール、買取エリア、買取対象、その他補足、お気に入り、メモ、登録日、更新日
- **案件・回答一覧CSV** — 1回答につき1行。業者名の隣によみがなを含みます。回答0件の案件も回答列を空にして出力します。

どちらもUTF-8 BOM、CRLF、ダブルクォート処理、Excel数式注入対策付きです。CSV入力はありません。

## PWA・iPhoneホーム画面・オフライン

HTTPまたはHTTPSで初回起動するとアプリシェルをService Workerへ保存します。iPhoneではSafariの共有メニューから「ホーム画面に追加」を選び、「買」の不透明180×180pxアイコンで起動できます。初回キャッシュ後はオフライン再起動できます。電話・メールなど外部URLはキャッシュしません。

Service Workerキャッシュ名は `kaitori-company-note-v1-prototype3` です。有効化時は `kaitori-company-note-` で始まる旧キャッシュだけを削除し、他アプリのキャッシュには触れません。各アセットへ試作3のバージョン識別子を付け、旧HTMLと新旧JS/CSSが混在しないようにしています。

初回インストールの `clients.claim()` では画面を自動再読み込みしないため、起動直後に開いた業者登録ダイアログや入力を閉じません。既存PWAの更新時だけ、未保存入力がないことを確認して1回再読み込みします。

## `file://` とHTTPの違い

| 機能 | `file://` | HTTP / HTTPS |
|---|---:|---:|
| 登録・検索・編集 | ○ | ○ |
| IndexedDB | 対応ブラウザで○ | ○ |
| JSON・CSV | ○ | ○ |
| Service Worker | × | ○ |
| PWAインストール | × | HTTPS等で○ |
| オフラインキャッシュ | × | 初回キャッシュ後○ |

`file://`、localhost、GitHub Pagesは別の保存元です。データは自動共有されないため、移行にはJSONバックアップを使用してください。

## 保存場所とデータ保護

業者・案件・回答は端末内のブラウザ保存領域にあり、外部送信されません。ただしSafariの「履歴とWebサイトデータを消去」、サイトデータ削除、端末初期化などで消える可能性があります。**定期的なJSONバックアップを推奨します。**

## 初期サンプル

初回だけ、新形式のよみがな・エリア・買取対象を持つサンプル業者を3社登録します。初期化済みフラグを維持するため、既存利用者や再読み込み時に再追加しません。詳細設定からサンプルだけを削除できます。

## 技術構成とデータベース

- HTML / CSS / JavaScript
- IndexedDB version 2
- `companies` / `settings` / `cases` / `caseResponses`
- PWA / Service Worker
- ローカル生成したApple Touch IconとPWA PNGアイコン
- 外部依存・外部通信なし

IndexedDBのストア構成は試作2と同じです。試作1から試作2へのv1→v2アップグレードで追加した案件・回答ストアと各インデックスを維持します。試作3の会社データ補完はDB versionを上げず、同じストア内の安全な読み書きトランザクションで行います。業者件数、ID、既存フィールド、案件、回答、設定、サンプル初期化済み状態、アーカイブ状態を維持します。

## 現在の制限

- IMEの読み候補取得はOS・ブラウザ・日本語入力方式に依存し、確定済み漢字からの読み推測はしません。
- ログイン、クラウド同期、複数端末同期、ユーザー権限はありません。
- 売主の個人情報、詳細登記、査定書、PDF・写真添付、契約・決済・手数料管理はありません。
- メール一斉送信、送信履歴、通知、自動リマインダー、稟議ワークフローはありません。
- CSV入力はありません。
- `file://` の保存永続性はブラウザ仕様に左右され、PWAキャッシュは使えません。
- iPhoneの電話・メールアプリ起動、ホーム画面追加、実Excelでの表示は端末設定にも左右されます。
- 案件種別と個別要因は試作3では固定候補です。
- 本格的なCRM、顧客管理、契約管理用途は想定していません。

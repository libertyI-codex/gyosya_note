# 買取業者ノート

**Kaitori Company Note — Ver.1.0 試作2**

不動産の買取案件が発生したときに、「この物件なら、どの買取業者へ声をかけるか」を素早く判断し、案件概要と各社回答を少ない入力で残す端末内保存アプリです。本格的な案件管理やCRMではなく、概要・回答金額・条件・見送り理由・次回確認日に記録範囲を限定しています。

ログイン、外部サーバー、外部API、CDN、外部フレームワークは使用しません。通常はIndexedDBへ保存し、利用できない環境だけブラウザの端末内互換保存へ切り替わります。

## 起動方法

### 1. `file://` で直接起動

`index.html` をダブルクリックするか、ブラウザで直接開きます。

- 業者登録・検索・編集・削除
- JSONバックアップ・復元
- CSV出力

は利用できます。ブラウザの制約によりService Worker、PWAインストール、オフラインキャッシュは利用できません。

### 2. ローカルHTTPサーバー

このフォルダをカレントディレクトリにして、例として次を実行します。

```powershell
python -m http.server 8765
```

ブラウザで `http://127.0.0.1:8765/` を開きます。HTTP起動ではService Workerとオフラインキャッシュを利用できます。

### 3. GitHub Pages

フォルダ内容をGitHub Pagesで公開してください。すべて相対パスなので、リポジトリのサブディレクトリでも動作します。PWAとして継続利用する場合は、HTTPSのGitHub Pagesが適しています。

## 画面構成

下部ナビゲーションは次の4画面です。

1. **探す** — エリア・買取対象・温度感・お気に入り・フリーワードで該当業者を検索
2. **案件** — 案件概要、打診先、各社回答、類似案件を確認
3. **業者** — 登録済み業者の確認、簡易絞り込み、並び替え、回答履歴
4. **その他** — 件数、次回確認、バックアップ、CSV、詳細設定、アプリ情報

右下の「＋」は、探す・業者画面では新規業者、案件画面では新規案件を開きます。

## 業者登録方法

1. 「探す」または「業者」の右下にある「＋」を押します。
2. 業者名を入力します。
3. 必要に応じて、担当者・電話・メール・エリア・買取対象・温度感・お気に入り・一言メモを入力します。
4. 「保存する」を押します。

必須項目は**業者名だけ**です。エリアや買取対象が未選択でも保存できます。電話番号とメールが明らかに不自然な場合は控えめな確認表示を出しますが、入力内容は消しません。

新規登録・複製時に、業者名の正規化一致、電話番号一致、メール一致が見つかると「同じ業者の可能性があります」と表示します。既存業者の詳細を確認するか、同名別会社としてそのまま登録できます。

## 買取業者の探し方

起動直後は「探す」画面です。

- 買取エリアは複数選択できます。
- 買取対象は複数選択できます。
- 温度感は「すべて／積極的／通常／現在休止」から選びます。
- 「お気に入りのみ」を切り替えられます。
- 業者名、担当者、電話、メール、エリア、買取対象、メモをフリーワード検索できます。

異なる分類はAND条件、同じ分類内の複数選択はOR条件です。たとえば「横浜」＋「土地・戸建」は、横浜に対応し、土地または戸建を買う業者を表示します。

広域タグは実務上の包含関係として扱います。たとえば「横浜」検索では、「横浜」に加えて「神奈川県全域」「関東」「全国」の業者も候補に含まれます。

探す画面の並び順は、お気に入り、温度感（積極的→通常→現在休止）、業者名の順です。

## お気に入り

業者カードまたは詳細画面の星を1回押すだけで切り替えられます。お気に入り業者は探す画面の上位へ表示されます。「お気に入りのみ」で絞り込みもできます。

## 温度感

- **積極的** — いま優先して相談する業者
- **通常** — 通常の相談先
- **現在休止** — 現在は仕入れを休止している業者

初期値は「通常」です。色だけでなく、カードと詳細画面へ必ず文字でも表示します。

## 業者画面と並び替え

初期表示は `Intl.Collator("ja-JP")` を使用した業者名順です。次へ切り替えられます。

- 業者名順
- お気に入り順
- 温度感順
- 更新が新しい順
- 登録が新しい順

業者名、お気に入り、温度感、エリア、買取対象で簡潔に絞り込めます。

## 業者詳細

業者名、担当者、電話、メール、買取エリア、買取対象、温度感、お気に入り、メモ、登録日・更新日を表示します。

- 電話する（`tel:`）
- メールする（`mailto:`、件名「買取案件のご相談」）
- 編集
- 複製
- 削除

削除前には業者名を含む確認を表示します。削除後は数秒間だけ「元に戻す」を利用できます。

業者詳細には、その業者へ打診した案件の回答履歴も表示します。過去回答、金額回答、見送り、成約の件数、最近の回答、対応した案件種別・個別要因を確認し、案件名から該当案件を開けます。

回答履歴がある業者を通常の削除操作で消すことはありません。「非表示にする」と業者をアーカイブし、通常の検索・一覧・新規案件候補から除外します。過去案件には引き続き表示され、「その他」→「詳細設定」から復元できます。完全削除は詳細設定だけに置き、実行時は紐づく回答も削除することを明示して確認します。

## 案件登録

案件画面の「＋」から登録します。必須は**案件名だけ**です。最初に案件名、所在地、案件種別、案件状況を表示し、個別要因・金額・面積・メモは折り畳んでいます。

- 所在地、エリア、エリア補足
- 案件種別（原則1つ）
- 個別要因（複数）
- 売主希望額（保存値は円）
- 土地面積・建物面積（保存値は㎡）
- 案件状況
- 案件メモ（500文字）

案件種別は、戸建1宅地、戸建分譲、一棟収益、区分M（空室）、区分M（OC）、土地、事業用地、店舗・事務所、ビル、その他の10項目です。内部IDと表示名を分離しています。「その他」だけ補足名を入力できます。

個別要因は、建築・造成（旧耐震、造成、崖・擁壁、狭小地、旗竿地、不整形地、再建築不可）、権利関係（借地、底地、立ち退き）、法令・土地特性（調整区域、山林、農地、既存不適格、埋蔵文化財）、売却事情・商品特性（リースバック、事故・心理的瑕疵）の4カテゴリです。指定リストにある全17項目を内部IDで保存します。

案件状況は、相談中（初期値）、買取打診中、回答待ち、回答済み、成約、見送りです。回答に応じて勝手に上書きせず、利用者が変更します。

## 各社回答

案件詳細の「業者を追加」から既存業者を複数選択します。追加直後は「打診済み」です。同じ案件・同じ業者の回答は1件だけで、IndexedDBの複合ユニークインデックスでも重複を防ぎます。

回答状況は、打診済み、回答待ち、金額回答、条件付き、見送り、成約です。必須は業者と回答状況だけです。回答金額、回答日、回答理由、回答関連要因、次回確認日、回答メモは任意で、金額未入力と0円を区別します。

回答理由は、金額が合わない、エリア外、物件種別対象外、個別要因が難しい、現在仕入れ休止、社内稟議否決、他案件を優先、条件付きなら検討可、その他から1つ選びます。回答関連要因は案件に登録した要因から選びます。後から案件側の要因を外しても、既存回答の選択は消さず「案件から外れた要因」と表示します。

回答カードは回答状況順（成約、金額回答、条件付き、回答待ち、打診済み、見送り）が初期値で、同順位は回答金額が高い順、未入力は下です。金額順、回答日順、業者名順へ変更できます。

## 案件検索・類似案件・おすすめ業者

案件一覧は更新が新しい順が初期値です。登録が新しい順、案件名順、最高回答額順、回答待ち優先へ切り替えられます。進行中、回答待ち、回答済み、成約、見送り、すべて、およびエリア・案件種別・個別要因・フリーワードで絞り込めます。フリーワードは案件概要に加えて、回答メモと業者名も検索します。

「類似案件」は外部APIやAIを使わず、案件種別一致、共通する個別要因数、エリア一致、更新日の新しさをこの順で比較します。同じ案件自身は候補から除外します。

案件へ業者を追加するときは、エリア一致、買取対象と案件種別の対応、お気に入り、温度感、同じ個別要因に対する過去回答件数を加点して並べます。すでに追加済みまたはアーカイブ済みの業者は候補に出ません。

## 次回確認

回答へ次回確認日を登録すると、「その他」で期限超過、今日、7日以内、それ以降に分けて確認できます。通知・自動リマインダー・外部送信はありません。

## JSONバックアップ

「その他」→「データのバックアップ」→「JSONバックアップを保存」を押します。全業者・案件・回答・設定を1ファイルへ保存します。

```json
{
  "format": "kaitori-company-note-backup",
  "appName": "買取業者ノート",
  "appVersion": "Ver.1.0 試作2",
  "schemaVersion": 2,
  "exportedAt": "ISO 8601日時",
  "companies": [],
  "cases": [],
  "caseResponses": [],
  "settings": {}
}
```

ファイル名は `kaitori-company-note-backup-YYYY-MM-DD.json` です。

## JSON復元

「その他」→「データのバックアップ」→「JSONから復元」でファイルを選びます。

- **現在のデータへ追加** — 既存データを残して追加。衝突する業者・案件・回答IDは新しいIDへ付け替え、回答の参照も追従させます。候補設定は現在値と統合します。
- **現在のデータを置換** — 確認後、業者・案件・回答・設定を同一トランザクションで置換します。

Ver.1.0 試作1の `schemaVersion: 1` も復元でき、案件・回答は空配列として扱います。schemaVersion 2では、各ID、参照先、同一案件・業者の重複、不正な案件種別・要因・回答状況・金額・日付まで、保存データへ触れる前に全件検証します。不正JSONや復元エラーでは既存データを変更しません。

## CSV出力

「その他」→「データのバックアップ」には2種類のCSVがあります。

- **業者一覧CSV** — 業者名、担当者名、電話番号、メール、買取エリア、買取対象、温度感、お気に入り、メモ、登録日、更新日。
- **案件・回答一覧CSV** — 1回答につき1行。案件概要、案件種別・要因、価格・面積、業者、回答状況・金額・理由・関連要因・日付・メモを出力します。回答0件の案件も、回答列を空欄にして1行出力します。

どちらもUTF-8 BOM付き、CRLF改行、全項目ダブルクォート、Excel数式注入対策付きです。CSV入力には対応していません。

## PWA・iPhoneホーム画面追加

HTTPまたはHTTPSで起動したとき、アプリシェルをService Workerへ保存します。iPhoneではSafariの共有ボタンから「ホーム画面に追加」を選択します。ホーム画面では「買」の専用アイコンで起動できます。

初回キャッシュ完了後は、通信がない状態でもアプリを再起動できます。業者データ自体はネットワークではなく、ブラウザの端末内ストレージから読み込みます。

## `file://` とHTTPの違い

| 機能 | `file://` | HTTP / HTTPS |
|---|---:|---:|
| 登録・検索・編集 | ○ | ○ |
| IndexedDB | 対応ブラウザで○ | ○ |
| JSON・CSV | ○ | ○ |
| Service Worker | × | ○ |
| PWAインストール | × | HTTPS等で○ |
| オフラインキャッシュ | × | 初回キャッシュ後○ |

`file://`、localhost、GitHub Pagesは別の保存元（origin）です。各起動方法のデータは自動共有されないため、移行にはJSONバックアップと復元を使ってください。

## 保存場所とデータ保護

業者・案件・回答情報は端末内のブラウザ保存領域へ保存され、外部送信されません。一方、Safariの「履歴とWebサイトデータを消去」、ブラウザのサイトデータ削除、端末初期化などで消失する可能性があります。

**定期的なJSONバックアップを強く推奨します。** バックアップファイルはiCloud Drive、社内の安全な保管場所などへコピーしてください。

## 初期サンプル

初回だけ、操作確認用のサンプル業者を3社登録します。すべて「サンプル」と表示され、実在する業者情報ではありません。「その他」→「詳細設定」→「サンプルデータをすべて削除」で一括削除できます。再読み込みのたびに追加されることはありません。

## 現在の制限

- ログイン、クラウド同期、複数端末同期はありません。
- 売主の個人情報、詳細な登記情報、査定書、写真・PDF添付、契約・決済・手数料管理はありません。
- メール一斉送信・送信履歴、通知、自動リマインダー、稟議ワークフローはありません。
- CSV入力はありません。
- 読み仮名項目を持たないため、漢字の並びは厳密な五十音順ではなく `Intl.Collator("ja-JP")` の照合順です。
- `file://` のIndexedDB永続性はブラウザ仕様に左右されます。
- iPhoneの電話・メールアプリの起動、ホーム画面追加、実Excelでの表示は端末側の設定にも左右されます。
- 案件種別・個別要因は試作2では固定候補です。指定本文は「18項目」と記載されていますが、列挙された候補は17項目のため、列挙内容を欠けなく17項目実装しています。
- 本格的なCRM、顧客管理、契約管理用途は想定していません。

## 技術構成

- HTML / CSS / JavaScript
- IndexedDB（DB version 2、`companies` / `settings` / `cases` / `caseResponses`）
- PWA / Service Worker
- SVG原本からローカル生成した不透明PNGアイコン
- 外部依存・外部通信なし

IndexedDB v1からv2へのアップグレードでは `cases` と `caseResponses` のストアと検索インデックスだけを追加し、既存の `companies` と `settings` を削除・再初期化しません。既存業者は読み込み時に `isArchived: false` 相当として扱い、サンプル初期化フラグも維持します。
